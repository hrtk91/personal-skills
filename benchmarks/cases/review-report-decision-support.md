# レビュー結果を読者が判断できる説明へ変える

状態: **比較候補**。2026-08-15に文章のリズム条件を3回比較したが、2勝1敗で必須条件の保持も安定しなかったため判断保留。構造と言葉の予備比較は基準条件が優位だった。

## 元になった記録

- 実際に起きたこと: `benchmarks/observations/review-report-hard-to-understand.md`
- 原因の候補: `benchmarks/hypotheses/review-report-hard-to-understand.md`

## 目的

レビューで見つけた項目をそのまま並べず、読者が重要な問題、理由、最初の修正を判断できる説明へまとめられるか評価する。

短さや専門用語の少なさだけを正解にしない。内容を落とさず、読者が必要な判断へ到達できることを測る。

## 開始時に使うもの

- 毎回同じ条件で比べるための材料一式: `benchmarks/fixtures/review-report-decision-support/`
- 説明へ必ず残す6件: `source-findings.md`
- 条件ごとの依頼文: `prompts/baseline.md`、`prompts/structure-treatment.md`、`prompts/vocabulary-treatment.md`、`prompts/rhythm-treatment.md`
- 変更点を分けて示す基準例: `comparisons/`
- 読者が内容を理解できたか確かめる質問: `comprehension-questions.md`
- 実行方法: 実行ごとに空の一時ディレクトリを作る。最初に`source-findings.md`と`prompts/baseline.md`だけを渡して基準版を生成する。文章のリズムを比べる場合は、その基準版を`baseline-output.md`として、`prompts/rhythm-treatment.md`と一緒に別の担当へ渡す。変更条件には元資料、基準例、他条件の依頼文を見せない。同じモデル、推論設定、道具の権限、最大文字数を使う。

`comparisons/`は期待する改善点を分けるための基準例であり、モデル出力の正解文ではない。各文書の意図は`comparisons/README.md`に記載する。文面の一致では採点しない。

## AIへ渡す依頼

`prompts/`の各文書をそのまま使用する。一つの実行へ複数の依頼文を混ぜない。

## 必ず満たす条件

全条件で次を満たす。

- [ ] 6件すべての意味を残す。
- [ ] 事実と、提案または未確認事項を混ぜない。
- [ ] 元資料にない事実や成功結果を追加しない。

構造だけ変える条件では次も満たす。

- [ ] 結論と最初に取る行動が分かる。
- [ ] 関係する指摘を、読者が一度に判断できる問題へまとめる。
- [ ] 各問題について、問題、理由、修正方向を近くに置く。
- [ ] 用語の選び方と説明の詳しさは基準条件から変えない。

自然な日本語を優先する条件では次も満たす。

- [ ] 読者が前の会話や内部事情を知っている前提を置かない。
- [ ] 必要な専門用語は残し、初めて出すときに意味と、この説明での役割を短く示す。読者の判断に不要な内部用語は普通の言葉へ直す。
- [ ] 専門用語や内部ラベルを並べて文を圧縮せず、多少長くなっても自然な日本語で説明する。
- [ ] 指摘の順序、並べ方、まとめ方は基準条件から変えない。

文章のリズムだけ変える条件では、同じ実行で生成した基準版と比べて次も満たす。

- [ ] 一文の主要な主張を一つにする。
- [ ] 冒頭の結論を短い文で示し、修飾を重ねない。
- [ ] 冒頭では一文に一つの判断だけを置き、対象の説明、理由、次の行動を後ろの文へ分ける。
- [ ] 条件、理由、例外、補足を一文へ詰め込みすぎない。
- [ ] 長い文を句点で分け、冒頭や話題の切り替わりでは一文ごとに段落を分ける。
- [ ] 長い説明が続いた後に、短い結論、要約、または話題を切り替える文を置く。
- [ ] 短文を並べること自体を目的にせず、文の長さに変化をつける。
- [ ] 見出し、指摘の順序、まとめ方、用語は基準条件から変えない。

## 起きてほしくないこと

- 指摘を減らして短く見せる。
- 専門用語をすべて消し、正確さを失う。
- 用語を別の難しい用語で言い換えただけで、意味や役割を説明しない。
- レビュー担当の分類や思考順をそのまま本文の順序にする。
- 問題、理由、修正を別々の節へ分散させる。
- 全件を同じ重要度に見せる。
- 比較用文書の表現をそのままコピーする。

## 内容を機械的に確認する項目

```text
1. `source-findings.md`の6件が成果物に対応付く
2. 元資料にない事実や成功結果を追加していない
3. 構造だけ変える条件では、結論と最初の行動が本文前半にある
4. 構造だけ変える条件では、各主要問題の近くに理由と修正方向がある
5. 構造だけ変える条件では、用語と説明内容が基準条件から増減していない
6. 自然な日本語を優先する条件では、初出の必要用語に意味と役割の説明がある
7. 自然な日本語を優先する条件では、指摘の順序とまとめ方が基準条件から変わっていない
8. 各成果物の文字数と基準条件との差を記録する。自然な説明に必要な増加は即不合格にせず、内容の追加と区別する
9. 文章のリズムだけ変える条件では、一文に複数の主要な主張を置いていない
10. 文章のリズムだけ変える条件では、見出し、指摘の順序、まとめ方、用語が基準条件から変わっていない
11. 冒頭の一文と段落を確認し、結論へ到達する前に長い修飾が続いていない
12. 冒頭の各文が、結論、理由、次の行動のうち複数を同時に説明していない
```

理解しやすさは`comprehension-questions.md`で人が確認する。単語数や見出し数だけで自動合否を決めない。

## 人が比較する項目

匿名化したA/Bを読み、次を優先して採用する。

1. 最重要の問題と最初の修正を正しく答えられる。
2. 問題と理由を正しく説明できる。
3. 6件の意味が欠けていない。
4. 不要な用語説明を求めずに読める。
5. 同程度なら短い方を選ぶ。
