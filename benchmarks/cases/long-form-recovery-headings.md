# 見出しだけで長文の論旨へ戻れるか

状態: **比較候補**。開始条件の不備を二回修正した後、題名で範囲を固定し、中心命題との関係を短く示す見出しが一題材で選ばれた。一般化には別題材での再確認が必要。

## 元になった記録

- 読みやすい正例: `benchmarks/observations/readable-long-form-recovery-points.md`
- 原因の候補: `benchmarks/hypotheses/readable-long-form-recovery-points.md`

## 目的

長い技術文書で本文の途中を読み飛ばしても、見出しから文書全体の主張と現在の節の役割へ戻れるか確認する。

## 開始時に使うもの

- `benchmarks/fixtures/long-form-recovery/headings-neutral.md`
- `benchmarks/fixtures/long-form-recovery/headings-argument.md`

両方とも同じ題名、中心命題、節数、節順を持つ。本文は見せず、見出しだけを比較する。一方は話題名だけを示し、もう一方は各節が中心命題をどう展開するか示す。

## 必ず満たす条件

- [ ] 題名と冒頭の中心命題が同じである。
- [ ] 利用者へ題名を提示する。
- [ ] 節数と節順が同じである。
- [ ] 見出し以外の文章を比較へ混ぜない。
- [ ] 条件名を伏せて利用者へ提示する。

## 起きてほしくないこと

- 語調の好みだけで選ぶ。
- 一方にだけ本文の情報を追加する。
- 見出しの具体性と、短文や段落など他の要素を同時に変える。

## 人が比較する項目

本文を読まず、次を確認する。

1. 見出しだけで、文書全体が何を主張するか説明できる。
2. 三番目の節が、全体の主張をどう支えるか説明できる。
3. 二番目から四番目を読み飛ばしても、最後の節が全体とどう関係するか推測できる。
4. 同程度なら短い見出しを選ぶ。

## 最初の比較結果

- A、Bとも不合格。
- 話題名だけの見出しは、何が問題なのか分からなかった。
- 中心命題との関係を示す見出しも、なぜその行動から始めるのか分からなかった。
- 原因は見出しだけではなく、冒頭に具体的な状況と問いがなかったことにある。
- 題材と導入を作り直すまで、このケースを採否へ使わない。

題材を作り直した次の比較では、利用者へ題名を提示しなかった。短い話題名の見出しから「デプロイの話」と骨子は推測できたが、DBマイグレーションという範囲は題名なしでは分からなかった。この比較も、題名を含めた実際の読み方を再現していないため、採否へ使わない。

題名を提示した再比較では、中心命題との関係を示す見出しが選ばれた。ただし、条件と行動を一つの見出しへ入れたため長いと評価された。次は意味を保ったまま、現在地と次の判断に不要な重複語を削る。

短くした見出しは概ね良いと評価されたが、すべて同じ位置へ読点を置いたため、読点の多さが気になった。短い見出しでは読点を既定にせず、誤読を防ぐ場合だけ使う。

読点を外した最終案は、利用者から問題なしと評価された。採用された形は、題名で対象範囲を示し、各見出しで中心命題との関係を短く示す。別題材で再現するまで、長文一般の規則へは昇格させない。
