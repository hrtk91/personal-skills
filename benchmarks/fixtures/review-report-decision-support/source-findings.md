# レビューで確認された事実

次の6件は、比較評価用に匿名化した文書レビューの結果である。比較する文章は、6件の意味を変えたり、都合の悪い指摘を削ったりしてはいけない。

1. 二つの評価ケース文書は、開始に使う比較材料または入力資料が未作成で、同じ条件から再実行できない。
2. AGENTSなしの条件にも、AGENTSに書かれたプロジェクト固有ルールの発見と適用を求めている。
3. 「ルールを思い出せなかった」と「先に示された具体案へ引っ張られた」を区別する比較がない。
4. 共有部品を作ること自体は常に誤りではないのに、集約全体の保存を担当するRepositoryの実装が薄い仲介処理になったら不合格という採点条件を置いている。
5. 起きたことを書く場所で、原因候補を整理する特定のスキルを使うことを、期待される正解として書いている。
6. 原因候補を整理するスキルを使う条件では、補助担当の構成も変わるため、スキルだけの効果を測れない。

このうち、開始状態がなく実行できないことが最初の停止理由である。まず評価ケース文書を「起きたことの記録」と「原因候補」へ戻し、比較材料と実行手順を完成させてから評価ケースへ進める。残りの指摘は、比較材料を作る過程で採点条件と比較順へ反映する。

## 読者

追加文書を直すか判断する開発者。評価の仕組みで使う内部用語をすべて知っているとは限らない。

## 読後に判断できる必要があること

- 一番先に直す問題は何か。
- なぜ今のままでは比較実験として成立しないか。
- どの文書を残し、どの文書をいったん戻すか。
- 次に何を作れば評価ケースへ進めるか。
