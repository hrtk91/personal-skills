# レビュー結果

内容を直した方がよい箇所が6件あります。

- 比較に使うサンプル一式がまだないのに、実行できるテストケースとして文書を作っています。同じ状態から繰り返し試せません。
- AGENTSがない条件にも、AGENTSにだけ書かれたプロジェクトのルールを見つけて守るよう求めています。
- 「ルールを思い出せなかった場合」と「先に示された案へ引っ張られた場合」を見分ける比較がありません。
- 集約を保存するRepositoryの実装が薄い処理になったら不合格としており、今回見つかった実装の形そのものを再び正解条件にしています。
- 起きたことを記録する欄で、特定の問題整理スキルを使うことが正解だと先に決めています。
- 問題整理スキルを使う条件では担当するAIの構成も変わるため、スキルだけの効果を測れません。

AGENTSがある場合だけ確認する項目と、全条件で確認する項目を分ける必要があります。また、実装の形は合否条件ではなく、原因を調べる際の参考情報へ下げます。問題整理スキルは最初から正解にせず、比較してから判断します。

まず、実行材料がない二つのテストケース案は、実際に起きたことと原因候補を記録する段階へ戻します。比較材料が完成してから、実行するテストケースへ進めます。また、ルールを判断直前に見せる条件と、具体案を先に見せる条件は、別々に比較します。
