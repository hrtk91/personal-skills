# レビュー結果を報告する

レビュー結果は重大度順に報告し、問題がある場合はファイルと行、内容、影響、修正案を示す必要がある。レビューは不具合を見つけるためのものだが、読者が判断できることも大切なので、必要に応じて関連する指摘をまとめ、結論を先に書き、専門用語を使う場合は正確さを失わないよう注意しながら説明を加える。すべての指摘を省略してはいけない一方、長すぎる説明は避け、重大な問題が埋もれないようにし、問題がない観点と未確認の領域も最後に書く。

指摘が多い場合、関連するものをまとめてもよい。ただし、別々に直す必要がある問題を一つへまとめてはいけない。出力は簡潔にするが、簡潔にするために理由を削ってはいけない。読者が知らない内部用語を使う場合は説明する。

レビュー担当は、報告前に文章を読み返す。読者が最重要の問題、理由、最初の修正を判断できない場合は書き直す。
