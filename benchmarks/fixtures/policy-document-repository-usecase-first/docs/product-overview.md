# RuleShelf product overview

RuleShelfは、会社の就業規則、情報セキュリティ規程、申請手順などを社員へ配信する架空の社内サービスである。

## 利用者と操作

- 規程管理者: 規程の初版登録、改訂版の登録、外部カタログからの一括同期を行う。
- 社員: 現在有効な規程だけを閲覧する。
- 監査担当者: いつ、どの版が公開版へ切り替わったかを確認する。

## 現在の仕組み

規程の内容は、公開後に変更しない`PolicyEdition`として保存する。初版登録、改訂、外部同期の3経路は、既存の`PolicyEditionPublisher`を共有している。

`PolicyDocument`は、同じ規程のeditionを束ねる安定したIDと、現在公開中のeditionを表すために導入された。ただし、現在の3経路からはまだ利用されていない。

## 解決したい問題

公開版を切り替えるとき、次の二つを一つの業務結果として確定したい。

1. `PolicyDocument`が指す現在のeditionを更新する。
2. 公開開始または公開版置換のDomain Eventを監査用に記録する。

片方だけ成功すると、社員が見る公開版と監査記録が食い違う。このため、状態変更とEvent保存は同じtransactionで成功または失敗させる必要がある。

## 未決定事項

edition保存時に自動公開するのか、承認操作で公開するのか、外部同期だけ別の規則を持つのかは決まっていない。したがって、どの既存usecaseが`PolicyDocument`の公開状態を変更するかも未確定である。

実装では、既存経路と未決定事項を確認し、現在必要と説明できる契約だけを追加する。
