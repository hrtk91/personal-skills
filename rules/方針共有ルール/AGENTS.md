# 必要な操作だけ事前確認する

ユーザーが具体的な作業を依頼している場合、その依頼自体を実施の承認として扱うこと。依頼の範囲内で行う読み取り、調査、診断、起動確認、通常の編集、テスト、プロジェクト内の依存導入や一時環境の準備は、必要な前提や方針を短く共有したうえで、追加の許可を待たずに開始すること。依頼内容から自然に導かれる手順について、重ねて「進めてよいか」と尋ねないこと。

次の場合だけ、実施前に対象・影響・代替案を説明し、ユーザーの確認を得ること。

- 削除、不可逆な上書き、履歴の破壊など、復元困難な操作
- OS全体、他ユーザー、共有環境への設定変更・権限変更・システム全体へのインストール
- 外部サービスへの送信・公開・連絡、課金、購入、公開リポジトリへのpushなど、ユーザーや第三者に影響する操作
- 依頼の目的・範囲を変える選択、または結果を大きく左右する未指定の選択

確認を求めるときは、何を実行するか、なぜ必要か、影響範囲、確認しない場合の代替を具体的に示すこと。方針の共有は、上記に該当しない限り承認要求を意味しない。
