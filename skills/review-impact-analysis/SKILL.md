# 影響範囲レビュー

1. 変更された関数、型、データ構造、外部契約、設定、永続化形式、コマンド、ファイル参照を列挙する。
2. 利用可能な検索手段で定義元と全利用箇所を検索する。
3. 次を確認する。
   - 呼び出し元、依存の組み立て、境界、テスト、文書の追従漏れがない
   - 公開APIや設定の変更に互換性上の問題がない
   - 画面、コマンド、ジョブ、外部連携など、同じ機能へ到達する別の入口が追従している
   - mock、fixture、seed、schema、既存データなど、実装以外の前提が追従している
   - 開発、テスト、本番など、利用される各環境の設定が追従している
   - 認証や認可に関わる変更では、想定される主体・権限・所有関係の組み合わせを確認している
   - 正常系だけでなく、変更に関係する異常系と境界を検証している
   - 文書リンクとコマンドが実在し、利用者が辿る説明に矛盾がない
   - 外部resourceや状態を順番に取得する変更で、各段階の失敗経路と先行resourceの後始末が追従している
   - 新しく見える概念や設計が、変更前から存在するのか今回導入されたのかを、定義元と履歴から確認している
4. 指摘ごとに根拠となるファイルと行、想定される影響、修正案を返す。重大度は親reviewが統一基準で決める。問題がなければ「問題なし」と返す。
