# Skill benchmark

skillは「良さそうな指示」を増やすのではなく、観測された失敗を再現し、原因をある程度切り分け、その介入で失敗を減らせたときだけ改善とみなす。測定できない微調整を続けない。

## 手順

1. **観測事実を固定する**
   - 実際に何を依頼し、何を期待し、AIが何をし、どう訂正して解決したかを書く。
   - 事実と「なぜ失敗したか」の解釈を分ける。
   - 再発していない低重要度の一件だけなら、まずobservationとして残す。

2. **失敗原因を一つに決め打ちしない**
   - `benchmarks/hypotheses/TEMPLATE.md` を使い、競合する原因仮説を置く。
   - 少なくとも、モデル能力、context探索不足、taskの曖昧さ、project固有前提、tool/環境、既存skillの副作用を候補として検討する。
   - 各仮説について「真なら何が起きるか」「何が出れば反証されるか」を書く。

3. **bare modelで識別する**
   - skillや追加の補助指示を外した現行モデルへ、元の条件に近い最小taskを与える。
   - 仮説間で結果が分かれるよう、変える条件は一つにする。
   - 対象失敗が再現しない場合は、原則としてskillを追加しない。task、context、tool、既存skillなど別要因を先に扱う。

4. **固定benchmark caseを作る**
   - 実運用で再現した失敗を優先する。
   - fixtureを新造する前に、既存repoのcommit/PRを固定して使えないか確認する。
   - 新規実装は空repoから開始してよい。
   - ケースには元のobservation / failure hypothesis、task、必須条件、悪化とみなす挙動、機械検査、人間評価を記録する。

5. **介入候補を選ぶ**
   - 原因に対して最も狭く、決定的な手段を選ぶ。
   - project固有の意思決定や前提なら `AGENTS.md`。
   - 再利用可能な探索・判断手順ならskill。
   - 忘れてはいけない保証ならtest、lint、型、DB constraint、CIなど機械的な手段を優先する。
   - 能力不足そのものならmodel routingや推論設定も候補にする。
   - skillを追加することを既定の解決策にしない。

6. **比較条件と合格条件を先に固定する**
   - 同じモデル、推論設定、ツール権限、開始状態、taskを使う。
   - baselineとtreatmentで変えるのは対象介入だけにする。
   - 何が改善し、何が悪化しなければ採用するかを結果を見る前に書く。
   - モデル名・version・設定を結果へ残す。結果はその構成に対する評価とみなす。

7. **baseline / treatmentを実行する**
   - 既定は各3回。出力が安定している場合だけ減らす。
   - 実装結果は毎回cleanな開始状態から作る。
   - 評価前に、どちらがbaselineか分からない形で成果物を並べる。

8. **機械判定と人間判定を分ける**
   - build、test、要件、禁止された変更など決定的に判定できるものを先に確認する。
   - 不定形な品質は、絶対点より「A/Bのどちらを採用するか」のblind pairwiseを優先する。
   - review系では、見つけるべき問題の見逃しと、根拠の薄い指摘を別に数える。

9. **採否を決める**
   - 事前に決めた合格条件を満たし、重大な要件・既存ケースを悪化させない場合だけ介入を残す。
   - 差が曖昧なら、指示や仕組みが少ないbaselineを残す。
   - 一つの低重要度な失敗だけから一般則を増やさない。

## 継続運用

- 日常利用で気になった出力はまずobservationとして事実だけ残し、その場でskillへ一般化しない。
- 同種の失敗が再発した場合、または高重要度ならfailure hypothesisと識別evalへ進む。
- 介入を変更したら、対象ケースだけでなく小さなregression setも再実行する。
- モデルを変更したらsmoke caseと過去の高重要度caseを再実行し、skillなしでも改善しているなら不要になったskillを削る候補にする。
- `skill-observation-recorder` 自身も推定器として扱い、人手でラベルしたsession集合に対するprecision / recallを定期的に確認する。
- benchmark自体の整備コストが介入の効果を上回らないよう、ケースは少数から始める。
