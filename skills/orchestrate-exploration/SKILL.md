# 探索オーケストレーション

親スレッドを探索の実行者ではなく、状態管理と判断を担うオーケストレーターとして運用する。

## 基本原則

- 親スレッドは、目的、成功条件、制約、確認済みの事実、仮説、判断、未解決事項を維持する。
- 実際の調査、ログ解析、実験、実装、テストは、役割に適したsubagentへ委譲する。
- 親スレッドはユーザー要求、重要な設計資料、既存方針を把握し、判断責任を手放さない。
- subagentの報告を結論として扱わず、証拠を確認し、必要に応じて原典をスポットチェックする。
- 長い会話や生ログを引き継がず、次の探索に必要な状態だけを圧縮する。
- 事実、推測、判断、未確認事項を混同しない。

このモードは通常のsubagent活用を置き換えない。単純な読み取り、変更箇所が明確な実装、一度で終わる確認には使わない。

## 親スレッドの責務

親スレッドは次を行う。

1. 探索の目的、成功条件、対象範囲、変更権限を確定する。
2. `State Capsule`を初期化し、探索中は唯一の現在地として更新する。
3. 次に減らすべき不確実性を一つ選ぶ。
4. 利用可能なagent枠を確認し、独立して実行可能な探索課題をsubagentへ渡す。
5. 報告の証拠、再現性、矛盾、対象範囲を評価する。
6. 必要なら別subagentへ反証、再現確認、レビューを依頼する。
7. 確認できた結果だけを`State Capsule`へ統合する。
8. 継続、分岐、方針変更、終了を判断する。

親スレッドは原則として、大量のコード読解、ログ全量解析、仮説ごとの実験、実装作業を直接行わない。ただし次は自身で行う。

- ユーザー要求と重要な制約の解釈
- 設計判断に必要な原典の確認
- subagentが示した証拠のスポットチェック
- agent間の矛盾解消
- 破壊的操作、外部変更、探索範囲拡大の判断
- 最終的な結論とユーザーへの報告

subagentを利用できない場合は、黙って通常作業へ切り替えない。このモードを継続できないことを伝え、通常モードへ移るかユーザーに確認する。

## State Capsule

開始時と各探索サイクルの終了時に、次の形式で状態を更新する。過去のCapsuleを継ぎ足さず、現在の状態へ置き換える。

```markdown
## State Capsule

### 目的と成功条件
- 

### 重要な制約
- 

### 確認済みの事実
- 事実 — 証拠:

### 現在の判断
- 判断 — 根拠:

### 有効な仮説
- 仮説 — 支持する根拠 — 反証条件:

### 棄却した仮説
- 仮説 — 棄却理由 — 再検討条件:

### 未解決事項
- 

### 次の探索
- 課題 — 完了条件:
```

圧縮時にも、重要な制約、否定結果、棄却理由、判断を覆す条件、未解決事項を消さない。詳細な時系列や生ログはCapsuleへ入れず、必要なら証拠の場所だけを残す。

長期保存や別セッションへの引き継ぎが必要な場合は、[exploration-state.md](assets/exploration-state.md)を作業場所へコピーして更新する。保存場所は既存のリポジトリ方針に従い、方針がなければユーザーに確認する。

## Subagentへの依頼

subagentには親スレッドの会話全文を渡さない。現在のCapsuleから、課題の実行に必要な情報だけを切り出す。

```markdown
## 探索課題
何を明らかにするか。

## 背景
なぜ今この課題を調べるか。

## 確認済みの事実
今回必要な事実だけ。

## 検証する仮説
仮説と反証条件。

## 対象と制約
対象範囲、読み取り専用か、変更可能範囲、禁止事項。

## 完了条件
何が分かれば終了するか。

## 報告形式
- 結論
- 証拠と参照場所
- 実行した操作
- 観測結果
- 仮説を支持または反証する理由
- 未確認事項
- 次に調べる場合の候補
```

一つのsubagentへ複数の曖昧な問いをまとめない。互いに独立し、同じファイルを編集しない課題だけを並列化する。実装を伴う場合も、親スレッドは調査結果と変更対象を確定してから、境界の明確な実装課題として委譲する。

agent階層を無制限に深くしない。原則として親スレッドだけが探索課題をdispatchし、実行担当はleaf agentとして再委譲しない。再委譲が必要な場合は、そのagentを中継役として明示し、子agent分を含む同時実行枠を事前に確保する。完了したagentは状態を確認し、実行中のagentを残したまま同じ枠を消費し続けない。

## 報告の統合

subagentの報告を次の順序で評価する。

1. 完了条件に答えているか確認する。
2. 結論を支える具体的な証拠があるか確認する。
3. 事実と推測が分かれているか確認する。
4. 対象範囲外の変更や仮定が混ざっていないか確認する。
5. 他の報告や既知の事実と矛盾しないか確認する。
6. 重要な主張を原典でスポットチェックする。
7. 採用、不採用、追加確認が必要、のいずれかへ分類する。

証拠が足りない場合は、親スレッドが穴を推測で埋めず、同じagentへの追跡依頼か独立した再確認を行う。

## 終了条件

次をすべて満たした場合に探索を終了する。

- 成功条件に対する答えが得られた
- 主要な結論に確認可能な証拠がある
- 重大な矛盾が解消されている
- 未解決事項と対象外事項が明示されている
- 結論が成立する範囲と、覆る条件が説明できる
- 実装を含む場合は、要求された検証が完了している

終了時は、最終的なState Capsuleを基に、結論、根拠、変更内容、検証結果、残る不確実性をユーザーへ報告する。

## 避けること

- 親スレッド自身が探索へ没入し、状態更新を後回しにする
- 会話全文や全ログをsubagentへ渡す
- subagentの結論を証拠確認なしで採用する
- 「失敗した」だけを記録し、条件や観測を残さない
- 棄却した仮説を無条件の永久決定として扱う
- Capsuleへ時系列ログを追記し続ける
- agentが実行中のまま完了と報告する
