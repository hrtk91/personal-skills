# Leaf subagent へのコンテキスト

## 目的

leaf に渡すのは、独立した因果仮説を立てて識別するための最小十分な packet だけにする。親の結論に同意させる情報、他 leaf の出力、全ログは渡さない。

## dispatch packet

各 leaf に次を順に渡す。

1. **役割と境界**: leaf であり、担当軸だけを探索し、外部への書き込みや子 subagent の起動をしないこと。
2. **問題設定**: 説明したい観測、決めたい意思決定、対象外、主問題設定、競合フレーム、主問題設定を棄却する条件。これは Axes 後の通常 leaf にだけ渡す。
3. **確定事実**: 出所付きの観測だけ。推測を事実として混ぜない。
4. **不明点**: まだ識別できていない変数と、必要なら欠落している資料。
5. **探索で守るべき制約**: セキュリティ、期限、コスト、変更禁止範囲、利用可能な観測手段。
6. **担当軸**: 一つの主担当。近接軸は探索を禁止せず、重複を避ける優先順位として示す。
7. **エビデンス**: 一次資料のパス・URL・行範囲、または短い抜粋。大きな資料は source map にする。
8. **出力契約**: `SKILL.md` の固定 Leaf フォーマット、最大2仮説、証拠不足なら不足情報を返すこと。

Probe の Reframing leaf と Wildcard leaf には、主問題設定、競合フレーム、親が列挙した探索軸を渡さない。確定事実、フレーム中立な意思決定の種類、制約、一次資料、出力契約だけを渡す。原因仮説や主問題設定の言い換えを意思決定の種類へ書かない。Reframing は別の問題設定を、Wildcard は隠れた前提または原因カテゴリを探す。親は Axes 確定直後に Probe の出力を Frame 時点の仮軸と採用 Axes へ照合して新規性を判定し、採否と理由を監査証跡へ残す。

## 実行環境の契約

通常は read-only の `explorer` を fresh context で起動する。dispatch 前に、起動 API / UI / agent 定義のいずれかで (1) fresh context、(2) 低推論、(3) read-only sandbox の三つを個別に読めることを確認する。いずれかを読めない、または値が条件外なら不合格とする。独立 leaf を起動せず、利用者に制約を示して判断を仰ぐか、冒頭バナー「独立性なし・単一 agent の逐次シミュレーション」および各項目の出所「親の仮説」を付けた親逐次モードへ切り替える。親逐次モードにも Reframing と Wildcard の2役を含める。親だけが dispatch し、leaf の再委譲を禁止する。

## 渡さないもの

- 親の暫定結論、推したい解決案、優先順位
- 他 leaf の出力、集約表、多数派の見解
- 全会話履歴、無関係なログ、未整理の長い検索結果
- token、cookie、パスワード、個人情報、アクセス可能だが不要な秘密情報
- 実行してよいように見える外部変更の指示

すでに棄却した仮説は、再提案を避けるために必要なときだけ「棄却理由と反証済み条件」を短く渡す。棄却したという結論だけを渡さない。Probe の leaf には渡さない。

## エビデンスの圧縮

親は詳細なエビデンスログを保持し、leaf には担当軸の判断を変え得る資料だけを渡す。

- コード・設定: ファイルパス、対象シンボル、関連する行範囲、実行時の観測を分ける。
- ログ: 全文ではなく、時刻、相関ID、失敗分類、前後の状態遷移を含む最小の連続区間にする。
- 文書・要件: 決定、制約、例外条件を抜粋し、解釈を事実として混ぜない。
- 大きい資料: source map にパスと検索語を書き、leaf に必要な箇所だけ読ませる。親の要約だけを唯一の証拠にしない。

負の結果、すでに失敗した方法、結論を覆す条件は、担当軸に関係する場合だけ必ず含める。これらを落とすと、leaf が同じ失敗を再発見する。

## prompt template

```markdown
あなたは低推論の leaf subagent です。fresh context で独立に探索し、担当軸以外の結論を出さず、
外部書き込み・設定変更・子subagent起動をしないでください。

## 問題設定
<観測事象、意思決定、対象外>

## 確定事実
- <事実>（出所: <user statement / file:line / log / URL>）

## 不明点
- <未確認の変数>

## 制約
- <守るべき制約>

## 担当軸
<一つの軸。対象外の近接軸も明記する>

## エビデンス
- <短い抜粋または source map>

`SKILL.md` の Leaf 固定フォーマットだけで、最大2仮説を返してください。
根拠になる観測事実には同じ形式の出所を必ず付け、参照元のない内容は推測として扱ってください。
仮説を識別できない場合は、不足している識別情報と、その情報で除外できる分岐を返してください。
```

Probe leaf（Reframing / Wildcard）用では、`問題設定` の主問題設定・競合フレーム・`担当軸` を省き、次を置く。

```markdown
## Probe の依頼
親が採用した問題設定、競合フレーム、探索軸を前提にしないでください。
- Reframing: 同じ観測をよりよく説明する別の問題設定を最大2件提案し、それぞれを識別する観測を示してください。
- Wildcard: 観測を説明し得る隠れた前提または原因カテゴリを一つ探してください。
親の分類との比較や「外側」の判定はしないでください。
```

## source map template

大きいリポジトリ、ログ、文書束には、raw artifact を丸ごと貼らず次を渡す。

```markdown
## Source map
- <path / URL>: <何が分かるか>; 読む箇所: <symbol / 行範囲>; 検索語: <terms>
- <path / URL>: <何が分かるか>; 読む箇所: <時刻範囲>; 検索語: <terms>
```

leaf が source map だけでは因果仮説を識別できないと返した場合、親は該当一次資料の最小抜粋を追加して fresh context の leaf として再実行する。親の結論で穴を埋めない。

この再実行は、新規 leaf ではなく同じ leaf の一回限りの再試行として扱い、総 leaf 数の上限に追加計上しない。再試行でも識別できなければ `I<id>` として残す。

## dispatch 前の確認

- packet だけで、leaf が何を説明し、何を決めず、どの軸を見るか判別できるか。
- Probe leaf に主問題設定、競合フレーム、親の探索軸を渡していないか。
- 確定事実と推測が分かれているか。
- 確定事実ごとに検証可能な出所があるか。
- leaf ごとのエビデンスが同じ結論を誘導していないか。
- 秘密情報と無関係な履歴を除いたか。
- 利用可能な agent slot、実効 reasoning effort、sandbox、fresh context を確認し、leaf からの再委譲を禁止したか。

## 回収後の確認

- 仮説が packet 内の根拠を越えて断定していないか。
- 仮説ごとに追加予測と反証条件があるか。
- 追加予測と反証条件が、隣接仮説と実際に分かれるか。分からなければ `I<id>` として不足情報へ戻したか。
- 同じ因果主張を別表現で重複していないか。
- 「追加で何を読めば分岐が減るか」という不足情報の報告を、失敗ではなく有効な出力として扱ったか。
